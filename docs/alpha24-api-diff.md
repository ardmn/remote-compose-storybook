# Remote Compose creation API: 1.0.0-alpha23 → 1.0.0-alpha24

The public API diff of the creation modules this catalog documents: `remote-creation-compose`,
`remote-creation-expression` (both `androidx.compose.remote`, 1.0.0-alpha23 → 1.0.0-alpha24) and
`foundation` (`androidx.compose.remote.foundation`, 1.0.0-alpha06 → 1.0.0-alpha07, the version
released with alpha24). `remote-creation` and `remote-creation-core` are creation modules too, but
their public `api/current.txt` did not change between the two releases (and has no composables).

## Where the API files come from

Each release's `api/current.txt` is taken from the androidx tree at the commit the release was cut
from. The commit was checked against the released `-sources.jar` files on Google Maven: every
Kotlin/Java source in the jar was hashed as a git blob and compared with the tree.

| Release | androidx commit | Evidence |
| --- | --- | --- |
| 1.0.0-alpha23 | [`a0e84553095`](https://github.com/androidx/androidx/tree/a0e84553095b1a585909a074ea21e2576e621087/compose/remote) | `remote-creation-compose-1.0.0-alpha23-sources.jar`: 212 of 212 sources identical (only the generated `R.java` is not in the tree); `foundation-1.0.0-alpha06-sources.jar`: 4 of 4. `remote-creation-expression-1.0.0-alpha23-sources.jar` has no sources (its API file is empty). |

## How the diff was made

The three API files of each release were parsed into types and members. Kotlin callers do not see
file facades (`…Kt` classes), so a top-level function is matched by package and name wherever its
facade is; `@BytecodeOnly` entries (Java bridges and `$default` methods) and `@InaccessibleFromKotlin`
getters of listed properties are left out. "Line" links go to the line of the API file at the release
commit (`compose` = `remote-creation-compose`, `expression` = `remote-creation-expression`,
`foundation` = `foundation/foundation`).

The big themes (release notes, change ids in brackets): the creation API no longer exposes Compose
UI types (new `Remote*` value types for content scale, blend mode, stroke cap/join, painting style,
path fill type, tile mode, compositing strategy, layout direction, role and the text styling types)
[I1dfb9, Id9ba1, Iace42, I1464b]; the state model moved to `remote-creation-expression` and its
constructors and `Companion.invoke` factories became top-level factory functions [I41115, Iff2f6];
`RemoteDrawScope` gained drawing, transform and clip functions [I2c823]; the text measurer was
replaced [I9022f]; named-state domains [Ibef77]; component positions [I67998]; and a round of
renames [Ia2573, I16acd].
